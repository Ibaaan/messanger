# Messanger

[English](README.md) | [Русский](README.ru.md)

## О проекте

Messanger — браузерный текстовый мессенджер, в котором можно зарегистрироваться, находить людей, создавать групповые чаты, обмениваться сообщениями в реальном времени и просматривать сохранённую историю переписки.

## Возможности

- Регистрация, вход и сохранение сеанса между посещениями.
- Смена пароля и выход из аккаунта.
- Поиск людей и создание групповых чатов.
- Отправка и получение текстовых сообщений в реальном времени.
- Просмотр сохранённых переписок и загрузка более ранних сообщений.
- Счётчики непрочитанных сообщений и синхронизация прочитанного между вкладками.

## Как запустить

### Локальный запуск (Bash)

Потребуются .NET 10 SDK, Docker с Compose и OpenSSL. Выполняйте команды из корня проекта в Bash.

1. Настройте и запустите PostgreSQL:

   ```bash
   cp .env.example .env
   docker compose up -d --wait
   ```

2. Создайте локальный ключ подписи:

   ```bash
   mkdir -p .local
   openssl genpkey -algorithm RSA \
     -pkeyopt rsa_keygen_bits:2048 \
     -out .local/jwt-private.pem
   ```

3. Настройте приложение в текущем терминале:

   ```bash
   export ConnectionStrings__Postgres="Host=localhost;Port=5432;Database=messanger;Username=messanger;Password=messanger_local_only"
   export Jwt__PrivateKeyPath="$PWD/.local/jwt-private.pem"
   ```

   Если вы изменили учётные данные базы данных или порт в `.env`, обновите строку подключения.

4. Настройте HTTPS, примените миграции и запустите приложение:

   ```bash
   dotnet dev-certs https --trust
   dotnet run --project Messanger -- --migrate
   dotnet run --project Messanger --launch-profile Local
   ```

   В Linux может потребоваться дополнительная настройка доверия к сертификату в зависимости от дистрибутива и браузера.

Откройте [https://localhost:7100](https://localhost:7100).

## Безопасность

- Пароли хранятся в виде хешей с солью.
- Для управления сеансами используются короткоживущие токены доступа и токены обновления с ротацией.
- Смена пароля завершает существующие сеансы и закрывает их активные соединения.
- Доступ к чатам и сообщениям контролируется проверками участия и ролей.
- HTTPS, защита от CSRF и ограничения источников запросов браузера защищают соединения и операции с сеансами.
- Ограничения частоты запросов и количества соединений помогают предотвращать злоупотребления.
